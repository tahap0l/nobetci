Kod imzalama politikası

Ücretsiz kod imzalama SignPath.io tarafından, sertifika SignPath Foundation tarafından sağlanmaktadır.

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

Durum: Nöbetçi, SignPath Foundation'ın açık kaynak kod imzalama programına başvurdu. v2.3.1 ve önceki sürümler kod imzalı değil. Başvuru kabul edilince her Windows sürümü aşağıda anlatıldığı gibi imzalanır; bu not ilk imzalı sürümle güncellenir.

Neler imzalanır

Windows'ta her sürümde üç dosya imzalanır: uygulama (nobetci.exe), Claude Code'un her kanca olayında çalıştırdığı aktarıcı (nobetci-hook.exe) ve ikisini taşıyan kurulum dosyası (Nobetci-<sürüm>-setup.exe).

İmzalanan her dosyada ürün adı Nobetci ve yayımlanan sürüm yazar; yazmayan dosyayı SignPath reddeder. Yalnızca bu deponun kaynak kodundan derlenen dosyalar imzalanır. Kurulum dosyasındaki değiştirilmemiş NSIS eklentileri bu sertifikayla imzalanmaz. WebView2 pakete konmaz: eksikse kurulum dosyası Microsoft'un kendi imzalı kurulumunu indirir.

macOS sürümleri, proje Apple Developer Program'a katıldığında Apple'ın Developer ID'siyle imzalanır ve Apple onayından geçer. Linux paketleri imzalanmaz; sürümdeki SHA256SUMS.txt ile doğrulanır.

Bir sürüm nasıl imzalanır

  • Sürüm, main dalından Release iş akışıyla elle başlatılır; yalnızca GitHub'ın kendi sunucularında çalışır.
  • İş akışı sürüm numaralarını denetler, testleri çalıştırır, uygulamayı ve aktarıcıyı o commit'ten derler.
  • İki program SignPath'e imzalama isteği olarak gider. Onaylayıcı isteğin Release iş akışından, main dalından ve yayımlanan commit'ten geldiğini denetleyip onaylar.
  • Kurulum dosyası imzalı programlardan oluşturulur ve ikinci istek olarak aynı şekilde onaylanır.
  • İmza denetlenir, SHA-256 değeri SHA256SUMS.txt dosyasına yazılır ve sürüm GitHub'da yayımlanır.

Ekip rolleri

  • Kod yazanlar ve gözden geçirenler: tahap0l (katkıda bulunanlar). Dış katkılar pull request olarak gelir ve ancak incelenip CI'dan geçince birleştirilir.
  • Onaylayıcılar: tahap0l. Her imzalama isteğine tek tek karar verir.

Ekipteki herkes GitHub'da ve SignPath'te çok adımlı doğrulama (MFA) kullanır.

Gizlilik

Bu program, kullanıcı ya da programı kuran veya kullanan kişi özellikle istemedikçe başka ağ sistemlerine hiçbir bilgi aktarmaz. Ağa çıkan özelliklerin hepsi (Mesaj Atölyesi, asistanın Burada sor seçeneği, hava durumu) sen açana kadar kapalıdır. Ayrıntılar gizlilik politikasında.

Sistemindeki değişiklikler

Nöbetçi yalnızca o anki kullanıcı için kurulur. Kancalarını ~/.claude/settings.json dosyasına ancak değişikliği ve tarihli yedeği gösterdikten sonra, sen uygula dediğinde ekler. Kaldırma aracı bu girdileri yedek alarak geri çıkarır.

İmzayı kontrol etmek

Windows'ta dosyaya sağ tıkla → Özellikler → Dijital İmzalar, ya da PowerShell'de Get-AuthenticodeSignature .\Nobetci-<sürüm>-setup.exe çalıştır. Bu depodan derlenmemiş imzalı bir dosya görürsen gizli olarak bildir.

Code signing policy

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

Status: Nöbetçi has applied for SignPath Foundation's open-source code signing. Releases up to and including v2.3.1 are not code-signed. Once the application is accepted, every Windows release is signed as described here, and this note is updated with the first signed version.

What is signed

On Windows, each release signs three files: the app (nobetci.exe), the relay Claude Code starts for each hook event (nobetci-hook.exe), and the installer that carries both (Nobetci-<version>-setup.exe).

Every signed file carries the product name Nobetci and the version being released, and SignPath refuses a file that doesn't. Only files built from this repository's source are signed. The unmodified NSIS plug-ins inside the installer are not signed under this certificate. WebView2 is not shipped: when it is missing, the installer downloads Microsoft's own signed setup.

macOS builds are signed with Apple's Developer ID and notarized once the project is enrolled in the Apple Developer Program. Linux packages are not signed; check them against the release's SHA256SUMS.txt.

How a release is signed

  • A release is started by hand from main with the Release workflow, which runs only on GitHub-hosted runners.
  • The workflow checks the version numbers, runs the tests, and builds the app and the relay from that commit.
  • The two programs go to SignPath as a signing request. An approver checks that it comes from the Release workflow, on main, at the commit being released, and only then approves it.
  • The installer is built from the signed programs and is approved the same way, as a second request.
  • The signature is checked, the SHA-256 goes into SHA256SUMS.txt, and the release is published on GitHub.

Team roles

  • Committers and reviewers: tahap0l (all contributors). Outside contributions come in as pull requests and are merged only after review and passing CI.
  • Approvers: tahap0l, deciding on each signing request.

Every team member uses multi-factor authentication for GitHub and for SignPath.

Privacy

This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. Every feature that reaches the network (Prompt Studio, the assistant's Ask here, the weather card) is off until you turn it on. Details are in the privacy policy.

Changes to your system

Nöbetçi installs for the current user only. It adds its hooks to ~/.claude/settings.json only after showing you the change and a dated backup, and only when you click to apply it. The uninstaller takes those entries out again, after another backup.

Checking a signature

On Windows, right-click the file → Properties → Digital Signatures, or run Get-AuthenticodeSignature .\Nobetci-<version>-setup.exe in PowerShell. If you find a signed file that was not built from this repository, report it privately.
